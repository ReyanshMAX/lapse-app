# Decisions

Settled architectural and product decisions. Do not reopen without new
information that directly invalidates a stated reason.

| ID | Decision | Chosen | Rejected | Reason | Date | Status |
|---|---|---|---|---|---|---|
| D-001 | Platform and stack | Native Swift / SwiftUI, iOS only | Expo / React Native; Expo + custom native module | The three hardest features (interval frame capture, animated overlay compositing, Live Activity) all require Swift regardless of wrapper. `ffmpeg-kit` was retired in 2025 with no maintained RN successor, so the export pipeline — the app's whole differentiator — has no JS path. Developer has ~1–2h/day of Mac access, which is enough for a native build loop | 2026-08-24 | active |
| D-002 | Session model | A session is a container of N clips spanning one study day | One continuous recording per sitting | iOS forbids background camera capture, so leaving the app is a hard teardown. Multi-clip is forced by the platform, not chosen | 2026-08-24 | active |
| D-003 | Time axis | Accumulated study time (sum of clip durations); paused wall-clock excluded | Wall-clock elapsed since session start | The user studies ~9h across a day with long gaps. Wall clock would report 14h for 9h of work and would make tag ranges, stats, and the overlay timer all meaningless | 2026-08-24 | active |
| D-004 | Session close rule | Auto-close at a configurable day cutoff, default 04:00 local; never close while actively recording — defer to next pause | Midnight boundary; idle timeout after N hours | User routinely studies past midnight, so a midnight cutoff would split a single study day in two. Idle timeout was explicitly rejected: a session paused at 14:00 and resumed at 20:00 is one study day | 2026-08-24 | active |
| D-005 | Source clip retention | Keep source clips after export; manual per-session delete | Delete sources after export to save space | Enables re-export at different speeds/overlays, is a prerequisite for the v2 AI focus analysis (which needs frames), and HEVC at a 3s interval costs only a few hundred MB for a full day | 2026-08-24 | active |
| D-006 | Capture interval | Fixed interval per session, default 2s, user-settable | 1s (too many frames); 3s (earlier default); 5s (user's initial preference) | Interval sets a hard floor on playback speed: export can drop frames but cannot invent them. At 5s/30fps the minimum speed is 150x, collapsing a 20-minute session to 8 seconds of video. Lower is more watchable at short lengths; 2s (60x floor at 30fps) was chosen over 3s (90x) for that, at ~50% more source storage — still only a few hundred MB for a full day (D-005). Changed 3s→2s 2026-08-27 by the account holder | 2026-08-24 (rev 2026-08-27) | active |
| D-007 | Speed selection | Chosen at export time, not capture time | Baked in during capture | Sources are retained (D-005) at a fixed interval, so speed becomes a pure export parameter and "fit to 30s" is free | 2026-08-24 | active |
| D-008 | Pomodoro mode | Cut entirely | Built-in Pomodoro with break segments excluded from the cut | Pause/resume already excludes break time from both the study-time axis and the exported video. Pomodoro would be a second, redundant mechanism | 2026-08-24 | active |
| D-009 | Social layer | Cut from v1 entirely | Strava-style friends feed, leaderboards, live presence in v1 | Requires network density the app will not have at launch; hours-studied is trivially gamed as a leaderboard metric; and user-generated content triggers Apple's reporting/blocking requirements. YPT already owns this space with ~5M users | 2026-08-24 | active |
| D-010 | Tagging model | Tag ranges over the study-time axis. v1 ships both the end-of-session segment list (default) and the drag slider (refine) | Session-level multi-tag with no time attribution; per-segment tap on pause | Session-level tags give tags but no per-subject time split, breaking stats. Tagging at pause adds friction to every pause. The segment list and slider are the same underlying range model, differing only in UI | 2026-08-24 | active |
| D-011 | Voiceover | v1. Non-destructive: audio stored as a separate layer keyed to the session, composited at export, never baked into stored video | v2; destructive bake-in | Without in-app voiceover the export goes to CapCut anyway, which is exactly the workflow the app claims to replace. Non-destructive costs little and makes retakes free | 2026-08-24 | active |
| D-012 | Overlay rendering | Burned into the exported video via `AVVideoCompositionCoreAnimationTool` | Separate movable layer applied post-export | Burned-in is far simpler and the export is meant to be immediately postable. Re-export from retained sources covers changing the overlay later | 2026-08-24 | active |
| D-013 | Backend | None in v1. No network calls at all | CloudKit sync; Supabase | Nothing to sync with a single device and no social layer. Zero network means the App Store privacy label is "no data collected", which is both the easiest review path and a genuine listing advantage | 2026-08-24 | active |
| D-014 | Audio at capture | Capture no audio. Export always carries a silent audio track | Record ambient audio during sessions | Timelapse audio is unusable at 100x+ speed. A silent track means voiceover mixes in without re-encoding the video track | 2026-08-24 | active |
| D-015 | Crash durability | Chunked writing: finalize the current clip every ~120s and start a new one. On launch, scan for unfinalized clips and recover what is readable | Single clip per resume, finalized only on pause | User accepts small loss on battery death or crash but not routine loss. Chunking caps worst-case loss at ~2 minutes. Clean exits lose nothing | 2026-08-24 | active |
| D-016 | Backgrounding behavior | Leaving the app auto-pauses and finalizes the current clip | Treat backgrounding as an error state or attempt to continue | The camera dies on background regardless. Leaving the app is a legitimate pause gesture — the user's rule is "phone usable only while paused, never while recording" | 2026-08-24 | active |
| D-017 | Live Activity | v1 | v2 | It is the one-tap path back into a paused session. Without it the pause-and-leave flow has enough friction to kill the day-spanning session model. It matters only while paused, since recording requires the app foregrounded | 2026-08-24 | active |
| D-018 | Charging | Assumed. Warn at session start below a battery threshold; no attempt to make long sessions survive unplugged | Aggressive power optimization to enable unplugged multi-hour sessions | Hours of camera plus screen-on is not survivable on battery. Dimming the screen reduces draw but does not change the conclusion | 2026-08-24 | active |
| D-019 | Export granularity (v1) | Whole session only | Arbitrary subrange export | Subrange export rides on the same range model as the tag slider and is cheap to add later. Whole-session keeps v1's export UI to one screen | 2026-08-24 | active |
| D-020 | Minimum iOS | 17.0 | 18.0; 16.0 | SwiftData and ActivityKit both need 17. Nothing in the feature set requires 18, and 16 would mean a hand-rolled persistence layer | 2026-08-24 | active |
| D-021 | Persistence | SwiftData for metadata; media files on disk referenced by **relative** path | Core Data; storing media as blobs in the DB | Container UUIDs change between installs, so absolute paths break. Media in the DB would make the store enormous and migrations slow | 2026-08-24 | active |
| D-022 | v2 AI focus analysis approach | On-device Vision framework for objective metrics; if natural-language feedback is added, send only derived numeric metrics to an LLM, never frames | Send captured frames to a vision model for qualitative feedback | Uploading video of the user studying would destroy the "no data collected" privacy label (D-013), cost money per session, and is unnecessary — face presence, head pose, and away-from-desk intervals are computable locally at near-zero cost | 2026-08-24 | active |
| D-023 | Interim build environment | GitHub Actions macOS runners: `StudyLapseCore` tests, a simulator compile check, and an **unsigned .ipa artifact** signed with a free Apple ID and sideloaded from Windows | Waiting for Mac access before starting; signing in CI with paid-program certificates; TestFlight | Mac access is unavailable for roughly a week. CI cannot sign for a device, but Sideloadly/AltStore sign an unsigned .ipa with a free Apple ID on Windows, so real device testing continues. The paid-account CI path was rejected for now: it costs a 20–30 min loop, needs enrolment lead time, and buys nothing Phases 0–6 require | 2026-08-24 | active |
| D-024 | Debugging during the no-Mac period | On-device debug log screen (ring buffer, copy to clipboard), built in Phase 1 | Relying on `os_log` console streaming; adding a crash/logging SDK | Sideloaded builds have no debugger and no console — `xcrun devicectl --console` needs a Mac. Without an in-app log there is no way to see why capture failed. A third-party SDK was rejected because it would add a network call and break the "no data collected" privacy label (D-013) | 2026-08-24 | active |
| D-025 | Xcode project definition | XcodeGen: a checked-in `project.yml`, with `StudyLapse.xcodeproj` generated on demand and git-ignored | Hand-maintained `.pbxproj` committed to the repo; Tuist | A `.pbxproj` cannot be created or safely edited without Xcode, and there is no Mac — CI would fail from the first commit. XcodeGen builds it from YAML on the runner, is editable from Windows, and eliminates `.pbxproj` merge conflicts. Tuist is heavier and solves problems this project does not have | 2026-08-24 | active |
| D-026 | Capture testability | A `FrameSource` protocol seam: `CameraFrameSource` (device) vs `SyntheticFrameSource` (CI), with all gating, chunking, writing, and persistence logic downstream of it | `CaptureController` owning `AVCaptureSession` directly | `AVCaptureSession` cannot run on a simulator, so a direct dependency would make the entire capture pipeline unverifiable in CI — which, with no Mac and no debugger, means unverifiable at all. The seam moves everything except real camera behaviour into automated tests | 2026-08-24 | active |
| D-027 | Repository visibility | Public repository | Private repository | GitHub bills macOS runner minutes at 10×, so a private repo's free tier yields roughly 200 macOS minutes per month — under 30 CI runs, consumable in a single unattended session. Public repos have unlimited free Actions minutes, which is what makes overnight agent runs possible at all | 2026-08-24 | active |
